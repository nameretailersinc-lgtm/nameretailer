## Information architecture and navigation

Six primary links, in this order: Marketplace (`/`), Services (`/content-writing-services/`), Tools (`/seo-tools/`), Guides (`/blog/`), About (`/about/`), Help (`/help-center/`). The brand also links home. Account and basket are utilities outside the primary link group; render only truthful session/basket state. A real guest account utility says `Sign in`, not Dashboard/Logout. Search has a consistent position. Help points to contact and real payment/refund instructions; keep it in the same relative order across templates.

Marketplace hubs expose retained DA, DR, traffic, TF, backlink and price intents through editorial links and filter controls. The 45 old segment pages are migration sources, not 45 navigation entries or automatically approved new landing pages. Every retained indexable segment needs a parent hub link plus a relevant contextual link. Conditional niche/country/language pages require inventory and editorial readiness; absent pages must not appear as published navigation destinations.

The tools hub groups all 29 individual tools into Metrics/research, Structured data/social, Images, Writing and General utilities; a tool may have one owning group plus contextual related links. Tools get breadcrumbs, related-tool links and useful guidance. Do not replicate the whole tool catalog in every header.

Services exposes managed guest posting, writing and genuine distinct retained service offers. Guides groups buyer education, metric explanations and content/tool usage. Do not expose community/review sections as active products until confirmed. No public indexable domain-detail pages; customer details remain authenticated/noindexed if commerce needs them.

Footer groups: Marketplace & services (selected hubs/process); Tools & guides (catalog and blog); Company & help (about/contact/support); Policies (existing privacy/cookie/refund/user-agreement/other reviewed legal destinations). Show owner-confirmed Name Retailer, info@nameretailer.com and Sharjah address consistently; do not invent a phone, legal suffix or opening hours. Add `Cookie preferences`, not a passive cookie-policy substitute. Necessary account utilities reflect session status.

Breadcrumbs use actual linked ancestors: Home -> Tools -> Word counter; Home -> Guides -> article; Marketplace -> metric hub. Current page is text with `aria-current="page"`; breadcrumb navigation has an accessible name and matches visible JSON-LD. A filter chip is not a new hierarchy level. Short legacy root slugs remain unchanged even where the visual breadcrumb indicates a group.

## Marketplace patterns

Facet order: keyword/domain search; niche; country; language; budget in USD; DA/DR; estimated traffic; advanced TF/backlink/spam/link attributes/turnaround. Expand acronyms and name source/date near data. Unknown must not become zero; traffic is an estimate, not observed audience. Use one meaning across desktop table and mobile cards.

Native labeled selects, checkboxes and min/max number inputs are the default. Validate range order, bounds and currency, and identify units. Provide `Apply filters` rather than firing disruptive updates on every keystroke. Applied chips have specific remove names such as `Remove language: English`; one `Reset filters` control clears criteria, preserves the page's owning hub where applicable, and announces the new count. A count reports matching inventory, not assumed dataset scale. Loading retains current content with `aria-busy`; a settled polite status announces one result count. Errors retain criteria and offer Retry; no results offers one-click relaxation of a criterion, not an empty grid.

Normalize query state so refresh/back/share restores filters and sort; no personal campaign data in URLs. SEO owns the allowlist and query contract. Arbitrary combinations are crawlable `noindex, follow` with normalized self-canonical; approved editorial clean hubs can index. Useful pagination has stable links and self-canonical pages, with filters retained and page reset on filter change. Avoid endless infinite scroll as the only traversal.

Default sort is transparent (`Recently updated` only if actual timestamps exist); otherwise explicit source order. Offer Price low/high, estimated traffic and relevant metric sorts, with a stable ID tie-break and unavailable values consistently last. Never label a sort `Recommended` without a documented rule. Table caption explains units; `<th scope="col">` identifies columns and row heading identifies publisher. Sort buttons expose `aria-sort` on the active header. Mobile cards use visible label/value pairs and the same source data; avoid two simultaneously accessible duplicate versions.

Guests can view public rows, filter, save a local shortlist and compare up to three entries. Local guest state contains listing IDs, not sensitive briefs, and storage failure falls back to session state with an explanation. A comparison shows relevance, source/date, inclusions, turnaround, price and unavailable data. Removing one item preserves the rest. `Add to basket` means actual saved basket state; production revalidates price/availability and explains changed or removed items before payment.

Only checkout requires account creation/sign-in. Preserve basket and intended step through authentication, merge duplicates predictably and allow review before payment. Explain placement/content scope, qualified paid-link attributes, currency, fees, delivery, refund/replacement terms and whether billing is one-time or recurring. Monthly/permanent meanings remain owner decisions; do not silently convert them into equivalent products or imply lifetime guarantees. Handle declined, canceled, pending and retried payment with truthful order state and no duplicate charge. Existing order/history migration remains unconfirmed.

Production mobile filter bottom sheet is a complete modal, preferably native `<dialog>`: named heading, focus on useful first element/heading, contained Tab navigation, background inertness, Escape/close, visible Apply/Reset and focus return to trigger. [W3C dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) supplies interaction guidance. The static preview may use an in-flow `<details>` disclosure with native keyboard behavior; it is not evidence that the production modal works.

## Search patterns

One plain GET search form remains useful without scripts. Full search results show query, type grouping and linked canonical destinations across tools, guides, pages/services and approved marketplace hubs; never expose private orders, drafts, customer data or domain details. Search results are noindexed and not in sitemaps. Editorial/database search excludes inactive redirects, test posts and unpublished conditional pages.

Progressive suggestions: minimum two meaningful characters, 200-300 ms debounce, cancel stale requests, cache public suggestions briefly, and cap the initial list to about eight. Treat these as initial design values, not measured performance. Enter submits full results unless a suggestion is actively selected. Empty input offers a few real task shortcuts; zero matches offers spelling/shorter-query help and a contact path; network failure preserves a working submit form.

Follow the [W3C editable combobox with listbox popup pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/): labeled input, `aria-expanded`, `aria-controls`, managed `aria-activedescendant`, stable option IDs, Arrow Up/Down navigation, Enter selection, Escape dismissal and normal text-editing keys. Keep DOM focus in the input; Tab moves onward, not into each option. Announce settled result count politely and avoid speech on each keystroke. Group labels and option accessible names include content type. No custom ARIA on a plain search form without suggestions.

## Reading and tool patterns

Article measure 60-75 characters, body around 18px on larger screens, generous line height and paragraph spacing. One project H1, logically nested section headings, direct answers under relevant questions, and a concise takeaways box. Do not force every heading into a question or every response into an arbitrary length when clarity suffers. Reading time is labeled an estimate computed from body words and a declared configurable rate, not invented research.

Show actual author/editor identity, publish date and genuinely updated/reviewed dates; missing identity is a labeled editorial requirement. Sources appear adjacent to claims. A desktop sticky TOC occupies its own column and never overlaps prose or focused links; on small/short viewports it becomes an in-flow collapsible contents list. Anchors use scroll margins matching the real header height. A relevant CTA follows the answer or article, with no entry popup. Related links connect the owning cluster and no unfinished destinations.

Tools lead with the input and a plain output explanation. Word-counter outputs define character/space counting and reading-time estimate; do not send input text to analytics. Image tools disclose actual local/server processing, file/type limits and deletion behavior. Require numeric crop coordinates/width/height, preset aspect ratios and resize inputs as alternatives to drag handles. Conversion preserves or clearly warns about lost transparency/metadata. Copy/download/reset actions have statuses, input retention and explicit errors. Remote tools show provider/source/date, quota, loading, unavailable and retry states; no simulated DR, backlink, traffic or keyword results. A missing provider produces a clear limit, not fabricated output. Do not claim a tool checks full WCAG conformance or Google's rich-result eligibility.

## Forms, authentication and admin

Use associated visible labels, appropriate `type`/`autocomplete` and explicit required/optional wording. Share Zod constraints between client/server. On attempted submit, retain values, place an error summary before the form, focus its heading/container and link each message to its field. Inline messages use `aria-describedby`/`aria-invalid` and plain actionable text (`Enter an email address such as name@example.com`). Validate gently on blur; do not mark untouched fields erroneous. Announce server success only after persistence/delivery acknowledgment; a failed send keeps data and offers Retry/working contact email. Duplicate submit prevention is reversible, and success replaces the form with acknowledgment and a meaningful next step.

Honeypot is inaccessible to users and assistive technology and cannot trap autofill; rate limiting and server verification support it. Cloudflare Turnstile has loading/failure/expiry states and a working accessible fallback route; do not assert its deployment alone makes a form accessible. Passwords, OTP and reset tokens permit paste and password managers; provide a labeled show-password button, relevant autocomplete, generic failure messaging and documented timeouts. Two-factor auth avoids cognitive puzzles and supports usable recovery. Login retains return context and validates allowed return destinations.

Admin lists share search, named filters, sort, results, pagination, row selection and a contextual bulk-action bar. A table distinguishes `select this page` from `select all matching`; destructive bulk actions show a count, reversible path where possible and confirmation. Preserve query state on return from edit. Role restrictions are enforced server-side and explain unavailable actions.

Editors have clear Draft/Scheduled/Published state, actual scheduled time with timezone, preview and revisions. Save and Publish remain separate buttons. Optional Ctrl/Cmd+S saves a draft; an optional modified Publish shortcut still requires explicit confirmation and must not interfere with editor/browser shortcuts. Avoid single-character shortcuts; users can disable shortcuts. Unsaved-change guards apply to navigation and timeouts; do not promise autosave until implemented. Authentication expiry preserves recoverable local draft state securely rather than reporting a false save.

SEO sidebar has title/description counters as guidance, not fixed Google limits or ranking scores. SERP preview is labeled approximate. Canonical/noindex/schema/redirect edits have explanatory help, validation and role-appropriate warnings. Upload requires an alt decision: meaningful text for informative media, or an explicit `Decorative` option storing `alt=""`. Logos linked without visible brand text need an accessible name. Do not force decorative artwork to have redundant descriptions. Dashboard warnings lead directly to affected records; orders/leads/media/redirects/users follow the same list pattern, with audit history and export progress/errors.

## Consent and privacy

Proposed product behavior, not a claim of legal compliance: a compact non-blocking choice with equally prominent Accept and Reject, plus Preferences. Optional categories default off; essential storage is explained. No page-entry marketing popup. Set denied consent defaults before tags can execute, and change consent only after choice; initialize GA4 only after analytics consent in the default basic-mode design, with Consent Mode v2 state wiring (`analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`). Ads-related states remain denied unless their corresponding purposes are actually approved. Google's [Consent Mode overview](https://developers.google.com/tag-platform/security/concepts/consent-mode) distinguishes basic tag blocking from advanced cookieless measurements; the proposed default is basic, and [implementation guidance](https://developers.google.com/tag-platform/security/guides/consent) controls command ordering. Meta Pixel loads only after marketing consent. A later withdrawal prevents future optional collection; it does not erase already transmitted data by itself.

Persist a versioned choice and expose `Cookie preferences` in every footer. Preferences use an accessible modal or in-flow disclosure, separate optional category toggles and Save/Cancel; avoid a second coercive prompt after Reject. The banner must not cover focused content or cause unexpected layout movement. Reserve space or use a bounded overlay with sufficient scroll padding for its actual height; at high zoom/reflow prefer in-flow placement. Test the banner with TOC/header/filter layers together. The owner must confirm actual purposes, retention, processors and reviewed policy text before launch.

## WCAG 2.2 AA implementation acceptance criteria

The normative target is [WCAG 2.2](https://www.w3.org/TR/WCAG22/). Semantic landmarks, a skip link to main, meaningful order/headings, visible focus, operable controls, labels and text alternatives are required implementation work. Use native anchors/buttons/forms/tables before ARIA. One H1 and preferred 44px controls are project conventions, not standalone AA criteria. Verify contrast/reflow/keyboard/error handling on real states, not only token swatches.

| Criterion / source | Concrete acceptance behavior |
|---|---|
| [2.4.11 Focus Not Obscured (AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | Header, TOC, banner, comparison bar and sheets cannot entirely hide a focused component. Project preference: whole focus outline and control visible. Verify top/bottom scroll boundaries |
| [2.5.7 Dragging Movements (AA)](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) | Crop/resize/sorting provide equivalent single-pointer actions without dragging, plus keyboard/numeric alternatives; keyboard alone does not satisfy the no-drag pointer requirement |
| [2.5.8 Target Size Minimum (AA)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | At least 24x24 CSS px or a documented criterion exception, including its spacing rule. Prefer 44x44 for primary/mobile controls. Inline text links have an exception; 44px is not the AA minimum |
| [3.2.6 Consistent Help (A)](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html) | Help/contact appear in consistent relative order across page sets; do not advertise unstaffed chat |
| [3.3.7 Redundant Entry (A)](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html) | Retain/select previous campaign, address and basket information within the same process unless a criterion exception applies; signing in does not discard entered order context |
| [3.3.8 Accessible Authentication Minimum (AA)](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html) | Customer/admin auth permits paste/password managers and offers assistance or a conforming alternative when a cognitive-function test would otherwise be required |

Additional product checks: body text 4.5:1 (large text 3:1), controls/meaningful graphical boundaries 3:1 where applicable; non-color status indicators; keyboard-only operation and no keyboard trap; text resize to 200%; reflow at 320 CSS px except justified two-dimensional table content; text-spacing overrides; descriptive page titles/links; errors and announced status; hover/focus popovers dismissible and usable; no rapid flashes; reduced-motion preference respected. Media/text alternative checks distinguish informative and decorative images. Test screen-reader table headers and mobile label/value relationships, not just visual card appearance. Full criteria and exceptions are in the normative source.
